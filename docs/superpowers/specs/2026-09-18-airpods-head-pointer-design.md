# AirPods 头部激光笔指针 — 设计说明

日期：2026-09-18  
状态：已批准  
范围：第一版桌面指向 + 点头左键。游戏不在本版实现。

## 1. 目标

做一个 macOS 菜单栏 App：戴着支持动态头部追踪的耳机，坐在主屏前，脸对着屏幕哪一块，鼠标指针就在哪一块；短促点头发出一次左键单击。

这是给本人用的短时工具（手临时没空时指向并点击），不是全天替代鼠标，也不是第一版游戏瞄准。

成功时用户能完成：授权 → 戴上兼容耳机 → 菜单栏开始并对准屏幕中心 → 头转向主屏四角时指针到对应区域 → 对着图标点头能点中 → 低头看桌面约 0.4 秒后指针不再跟随 → 抬头后恢复 → 用手动机/触控板时头控立刻让路、停手约 1 秒后头控恢复 → 摘耳机后指针停在原地。

## 2. 非目标（第一版明确不做）

- 眼动、摄像头、肩窥/防窥
- 多显示器：指针不跟到旁边的屏
- 摇杆式映射（头歪着停住时指针继续滑）
- 右键、拖拽、双击、悬停点击
- 默认常开的全屏准星层
- 具体游戏、FPS 瞄准、躲闪玩法
- 开机自启
- 完整快捷键自定义页
- iPhone 中转姿态（macOS 13 及更早不能靠本机 API 读耳机，第一版不补这条路）
- 头指向位置与外设位移叠加（鼠标当偏移量）；外设与头控的关系见 6.5，采用「外设让路」而不是叠加

游戏作为二期：本版把「姿态源」和「映射/手势」分开，二期只换映射规则，不换读传感器的方式。

## 3. 用户与环境

App 按**公开 API 的上下限**做，不绑某一台开发机。运行时只认 `CMHeadphoneMotionManager.isDeviceMotionAvailable`，不维护蓝牙 PID 白名单。

**macOS**

| | 版本 | 说明 |
| --- | --- | --- |
| 部署目标（最早） | **macOS 14.0 Sonoma** | 本机读取耳机姿态的 API 从这一版才有。13 及更早不支持，第一版不做 iPhone 中转 |
| 往后 | **macOS 15、26 以及仍提供该 API 的后续系统** | 用系统 SDK 编译，运行时做可用性检查。新系统只要 API 还在就应能跑 |
| 本机开发 | 15.7.9（MacBookPro15,1，Intel） | 开发与测试用，不是最低版本 |

二进制打 **Universal**（`x86_64` + `arm64`）。Intel Mac 能否真正出数，以该机连接兼容耳机后 `isDeviceMotionAvailable` 为准：API 标注是 macOS 14+，未写死芯片；Mac 上空间音频介绍曾写 Apple 芯片。Intel 上若为 false，菜单走「断开 / 不支持」文案，不得当成静默失败。

**耳机**

- 判定：已连接且 `isDeviceMotionAvailable == true`。未来带动态头部追踪的 AirPods / Beats 应能直接用，不必改名单。
- 官方「空间音频 + 动态头部追踪」范围（本版按此理解兼容面）：AirPods Pro 全代、AirPods Max、AirPods 3、AirPods 4（两款）、Beats Fit Pro、Beats Studio Pro、Beats Solo 4、Powerbeats Pro 2、Powerbeats Fit。
- 明确不支持：AirPods 1 / 2、无动态头部追踪的 Beats（如 Studio Buds 一类）、普通第三方蓝牙耳机。
- 本机测试设备（不是支持列表）：初代 AirPods Pro（蓝牙名「AirPods Pro」，PID `0x200E`）、AirPods 4 降噪款（蓝牙名「宅小年AirPods」，PID `0x201B`）。

**其它**

- 实现前需要完整 Xcode；本机现仅有 Command Line Tools。Intel 开发机应装 **Xcode 26.3 Universal**（或同代仍支持 Sequoia 15.6 的 Universal 包），不要装仅 Apple Silicon、也不要装要求 macOS 26.2+ 的 26.4/27。
- 界面语言：中文
- 显示名：头部指针；bundle id：`local.edison.headpointer`
- 灵敏度写入 `UserDefaults`，其余状态不持久：App 启动后一律为「关」

## 4. 交互形态

菜单栏常驻，无主窗口（`MenuBarExtra` / 等价的 status item）。

菜单内容必须包含：

- 开始 / 停止追踪
- 重新校准
- 暂停开 / 关（手动，与低头自动暂停是「或」关系，见 6.4）
- 灵敏度滑杆（一个，同时缩放水平和垂直）
- 实时相对 yaw、pitch（度数，保留 1 位小数）
- 当前状态文案
- 运动权限、辅助功能权限的状态，以及跳转系统设置的入口

图标四态，不可合并：

| 状态 | 含义 |
| --- | --- |
| 关 | 未开始追踪 |
| 追踪 | 正在用头移指针 |
| 暂停 | 手动暂停、低头自动暂停、或外设让路（指针不由头控写） |
| 断开 | 已开始过追踪，但耳机未连接或不在耳中 |

快捷键（第一版写死，菜单里用文字标出；与系统或现有软件冲突时再改，本版不做设置页）：

| 动作 | 默认 |
| --- | --- |
| 开始 / 停止 | ⌃⌥⌘H |
| 重新校准 | ⌃⌥⌘R |
| 暂停开 / 关 | ⌃⌥⌘P |

菜单在「关 / 断开」显示「开始」，在「追踪 / 暂停」显示「停止」。快捷键 ⌃⌥⌘H 与之相同：关或断开 → 尝试开始；追踪或暂停 → 停止到「关」。

⌃⌥⌘R 在关或断开时无效。⌃⌥⌘P 在关或断开时无效。

实时角度：追踪或暂停时显示相对原点的 yaw/pitch（含外设让路期间）；关与断开显示「—」。

暂停时菜单状态文案须区分原因，三选一优先显示：手动暂停 ＞ 低头暂停 ＞ 外设优先。

## 5. 架构

采用方案 1：原生 macOS 菜单栏 App。Swift + SwiftUI 菜单栏 + Core Motion + CoreGraphics 事件。部署目标 macOS 14.0，Universal 二进制。

```text
AirPods IMU
  → 姿态源 HeadMotionSource
  → 相对原点（校准帧的逆）
  → 低头暂停门闩 LookDownPause
  → 外设让路 PeripheralYield
  → 点头检测 NodClickDetector（仅未暂停）
  → 屏幕映射 ScreenMapper（死区 + 灵敏度 → 主屏 CG 坐标）
  → 指针驱动 PointerDriver（mouseMoved / 左键单击）
```

二期游戏只替换 `ScreenMapper`（以及可选的手势解释），不替换 `HeadMotionSource`。

### 5.1 组件职责

**HeadMotionSource**  
读 `CMHeadphoneMotionManager`，对外提供连接状态、原始姿态，以及校准后的未平滑相对姿态。不决定指针位置，不发鼠标事件。

**LookDownPause**  
根据**平滑后**的相对 pitch 和保持时间决定是否进入自动暂停。不负责手动暂停或外设让路。

**PeripheralYield**  
识别「不是本 App 写下的」指针移动或按键，在让路窗口内禁止头控写指针、禁止点头点击。不改手动暂停开关，也不改校准原点。

**NodClickDetector**  
仅当三种暂停来源均为假时，根据相对 pitch 的短时波形判定一次点头。只产出「单击」事件，不自己发系统点击。

**ScreenMapper**  
把相对 yaw/pitch 映射到系统主屏（菜单栏所在屏）上的一点。应用死区、灵敏度、平滑。

**PointerDriver**  
唯一调用 `CGEvent` 的地方：移动指针、左键按下抬起。未获辅助功能权限时成为空操作。

**AppState**  
菜单栏与快捷键的唯一状态机：关 / 追踪 / 暂停 / 断开，以及校准原点、手动暂停开关、低头暂停、外设让路、灵敏度。

各组件只通过明确的数据结构通信，不互相拿对方的私有队列或 manager 实例。

### 5.2 采样数据结构

姿态源每帧输出：

```text
HeadPoseSample
  timestamp: TimeInterval
  yaw, pitch, roll: Double          // 相对校准原点，弧度
  rotationRateX/Y/Z: Double         // rad/s
  sensorLocation: left | right | default
  connected: Bool
```

相对姿态算法（与 WWDC 一致）：先拷贝当前 `CMAttitude`，再 `multiply(byInverseOf: origin)`。校准前不得向映射层送数。

## 6. 行为细则

符号以实测为准：实现时戴耳机分别向左转、抬头，若与「指针向左 / 向上」相反则乘 -1。规格按用户感知描述，不按 IMU 原始轴描述。

### 6.1 开始、停止、校准

- **开始**：运动权限未授权则失败，留在「关」，菜单提示去开「运动与健身」。耳机 `isDeviceMotionAvailable == false` 或未连接则进入「断开」，不移指针。运动已授权且耳机可用：把开始那一瞬的姿态锁为原点，进入「追踪」。辅助功能未开时仍进入追踪并更新角度数字，但 `PointerDriver` 不发事件，菜单标明「未授权辅助功能，指针不会动」。辅助功能已开时，立刻把指针放到当前姿态映射到的屏幕点（正对原点则屏幕中心）。
- **停止**：停止向系统送鼠标事件，丢弃原点，进入「关」。指针留在停止那一瞬的位置。
- **重新校准**：仅在「追踪」或「暂停」时有效。把当前姿态重新锁为原点；未暂停则把指针移到屏幕中心；暂停中只更新原点，不移动指针。
- 开始本身包含一次校准，不要求用户先点校准再点开始。

### 6.2 激光笔映射

- 参考系：校准后的相对 yaw = 左右，相对 pitch = 上下。
- 主屏矩形：`NSScreen` 中带菜单栏的那一块。坐标给 `CGEvent` 用，原点在屏幕左上，Y 向下。
- 默认满屏角度（灵敏度滑杆 = 中点）：
  - 相对 yaw 的绝对值达到 22° → 指针到左缘或右缘
  - 相对 pitch 的绝对值达到 14° → 指针到上缘或下缘
- 灵敏度滑杆：只缩放这两个角度阈值。滑向「灵敏」时阈值变小（头少转就到边缘），滑向「迟钝」时阈值变大。两端钳制：水平阈值范围 12°～40°，垂直按同样比例跟随水平变化（保持 14/22 的比例）。
- 死区：±2°，不随滑杆改变。对平滑后的角 `a`、满屏阈值 `maxA`：

```text
if abs(a) <= 2°:     t = 0
else:                t = sign(a) * (abs(a) - 2°) / (maxA - 2°)
t = clamp(t, -1, 1)
```

`t = -1 / 1` 对应那一轴的屏幕边缘。两轴独立，再合成主屏上的点。这样离开死区时指针从中心连续向外走，不会在 2° 处跳变。
- 超出满屏角度：`t` 夹在 ±1，指针停在主屏边缘，不进入其他显示器。
- 平滑：只用于 `ScreenMapper` 和 `LookDownPause`。对相对 yaw/pitch 做指数滑动平均，新值权重 0.35。`NodClickDetector` 必须用未平滑的相对 pitch，否则短点头会被滤掉。
- 头在某一姿态停住：指针必须停在对应像素，不得继续滑动（激光笔，不是摇杆）。

### 6.3 点头单击

仅当状态为「追踪」（未暂停、未断开）时检测。使用**未平滑**的相对 pitch。

一次有效点头，必须同时满足：

1. 相对低头方向出现一次短促峰值：相对「点头开始前 150ms 内的 pitch 基线」，向下增量 ≥ 8°
2. 从开始低头到回到基线 ±3° 以内，总时长在 120ms～450ms
3. 过程中相对 yaw 偏移不超过 10°（排除转头被当成点头）
4. 距离上一次成功点击 ≥ 300ms

满足则 `PointerDriver` 在当前指针位置发送一次左键 down + up。不要把指针先移走再点。

暂停中（手动、低头自动、外设让路）点头必须忽略，不得点击。

### 6.4 暂停

三种暂停来源，任一为真则状态为「暂停」：不发送头控 `mouseMoved`、不检测点头。外设自己产生的移动和点击照常到达系统，App 不得吞掉、不得禁用鼠标或触控板。

**低头自动暂停**

- 触发：平滑后的相对低头角 ≥ `当前垂直满屏角 + 8°`（默认满屏 14° 时，阈值 22°），并且连续保持 ≥ 0.40s
- 恢复：相对低头角回到阈值以下超过 0.15s。恢复后继续用原校准原点，不重新校准，指针从冻住位置按当前姿态重新映射（可能一次跳到新位置，这是激光笔的正确行为）
- 设计意图：看 Dock / 屏幕下缘仍在追踪；看键盘或食物才冻住

**手动暂停**

- 菜单或 ⌃⌥⌘P 翻转手动暂停开关
- 手动暂停为开时，即使脸正对屏幕、外设已停也保持暂停
- 低头自动暂停结束、外设让路结束，都不会清掉手动暂停；手动恢复时若仍在低头阈值内或让路窗口内，继续保持对应自动暂停

**断开**

- 追踪或暂停中收到断开（入耳检测摘下或蓝牙断开）：立刻停止运动更新，清空点头缓冲，进入「断开」，指针停在原地。
- 不要因重新戴上而自动恢复追踪。
- 「断开」时点「开始」：若已连上且运动已授权，重新校准并进入追踪；若仍未连上，留在「断开」。
- 「断开」时点「停止」：进入「关」。

### 6.5 外设让路

激光笔每帧会把指针设到头指向的像素。若不让路，手动机/触控板刚挪开的位置会在下一帧被拽回。第一版采用 **外设一动，头控让路**，不采用「头位置 + 鼠标偏移」叠加。

**什么算外设活动**

- 指针位置与本 App 上一帧写下的位置相差超过 2 像素（容忍抖动），或
- 发生了本 App 没有发出的鼠标按下 / 抬起 / 拖拽 / 滚轮

必须排除本 App `PointerDriver` 刚 post 的事件，否则会把自己的移动当成外设，把头控停掉。触控板、外接鼠标、其它辅助功能设备同等对待。

**让路窗口**

- 检测到外设活动：立即进入让路，头控不再 `mouseMoved`、不再点头点击；外设完全接管指针
- 距离最近一次外设活动满 **1.0 秒** 且三种暂停里只剩让路：退出让路，恢复头控
- 恢复时不重新校准；指针按当前姿态映射，可能从外设停下的位置跳到脸朝向的位置（激光笔的正确行为）
- 让路期间角度数字继续更新
- 让路不改变手动暂停开关，也不等于用户点了「暂停」

### 6.6 指针驱动

- 使用 `CGEvent` 的 `mouseMoved` 与 `leftMouseDown` / `leftMouseUp`，`post` 到 `.cghidEventTap`，以便其它 App 收到事件。不要把 `CGWarpMouseCursorPosition` 当主路径（往往只瞬移指针，其它 App 收不到鼠标事件）。
- 未获辅助功能权限时：不发事件，菜单标明未授权。
- 点击坐标 = 发出点击那一帧的指针位置，与屏幕映射结果一致。

## 7. 权限与 Info.plist

- 必须有 `NSMotionUsageDescription`，文案：「读取 AirPods 头部姿态，用来移动鼠标指针。」缺此键时系统会在启动运动更新时直接终止进程，视为缺陷。
- 运动与健身：用 `CMHeadphoneMotionManager.authorizationStatus` 展示；未定局时在用户点「开始」时触发系统对话框。
- 辅助功能：用 `AXIsProcessTrusted` 检测；未授权时菜单提供跳转「系统设置 → 隐私与安全性 → 辅助功能」。
- App 必须是带 bundle id 的 `.app`，不能是无 Info.plist 的脚本。

## 8. 错误与边界

| 情况 | 行为 |
| --- | --- |
| 无兼容耳机 / `isDeviceMotionAvailable == false`（含 Intel Mac 上 API 不可用） | 开始后进入断开，不移指针，菜单说明：需要支持动态头部追踪的耳机，且本机系统能提供头部运动数据 |
| 运动权限拒绝 | 不调用 `startDeviceMotionUpdates`；开始失败并提示去系统设置 |
| 辅助功能未开 | 可显示姿态数字（若运动已授权），但不移指针、不点击 |
| 追踪中摘下（入耳检测） | 断开回调 → 「断开」，冻指针 |
| 原点漂移（换坐姿） | 不自动重锁；用户用校准或再点开始 |
| 多屏 | 指针夹在主屏边缘 |
| 快捷键冲突 | 第一版不检测冲突；用户反馈后再改默认 |
| 追踪中使用外接鼠标 / 触控板 | 头控立即让路；外设可移动和点击；停手 1.0 秒后头控恢复 |

## 9. 验证（手动，第一版不强制自动化测试文件）

1. 戴兼容耳机（本机可用初代 Pro 或 AirPods 4 ANC），选为 Mac 音频输出，授权运动与辅助功能。开始后确认 `isDeviceMotionAvailable` 为真；Intel 开发机上若为假，记为环境限制，菜单应走断开说明而不是崩溃。
2. 看主屏中心，点开始：指针到中心附近（±死区）。
3. 头转向主屏四角：指针到对应象限，停住头则指针停住。
4. 对着一个图标短点头：发生一次左键，图标被点中；连续快速点头不会在 300ms 内连点两次。
5. 低头看桌面/键盘并停住 ≥ 0.4s：状态变暂停，再点头不点击，指针不跟头。
6. 抬头回屏幕：恢复追踪，指针跳到当前朝向对应位置。
7. 灵敏度滑到两端：到边缘所需转头幅度明显变小/变大。
8. 摘一耳或放回盒：状态断开，指针停。
9. 未开辅助功能时：角度数字可动，系统指针不动。
10. 追踪开着时用外接鼠标把指针挪开并点击：指针跟手走、能点中；其间点头不点击。停手满 1 秒后头控恢复，指针跳到当前脸朝向。

## 10. 二期接口预留（不实现）

`HeadMotionSource` 保持本版形状。游戏若做相对瞄准或甩头指令，新增另一个 Mapper，不要改激光笔 Mapper 的默认行为。本版不得为「以后可能的游戏」加开关、配置或第二种映射。
